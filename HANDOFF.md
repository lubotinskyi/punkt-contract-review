# Передача проекта следующему разработчику

Состояние на 17 ноября 2026 года. Это снимок двух рабочих версий, а не обещание завершённого юридического продукта.

## Назначение и принцип работы

Юрист загружает договор поставки, типовую форму, положение о закупках и, при наличии, спецификацию и справочник поставщиков. Система формирует замечания с точными цитатами. Категория проверки отделена от решения юриста. Итоговый протокол содержит принятые замечания; сохранение правок сбрасывает подтверждение.

Не обучаем LLM на загруженных документах. В основной версии агент получает фрагменты через инструменты поиска и чтения. Демонстрационный режим выполняет фиксированные числовые проверки без LLM.

## Что уже работает

- Основная версия: загрузки DOCX, текстового PDF, TXT/MD/CSV/JSON; неизменяемые версии документов.
- Формализованные проверки явно указанных сроков, предоплаты, гарантии, итоговой суммы; ИНН и локальный справочник.
- Локальный TF-IDF поиск. Опциональный путь с sentence-transformers реализован отдельно.
- Замечания с проверкой существования цитат и источников; редактирование и собственные замечания юриста.
- SQLite, открытие истории, сохранение промежуточного состояния агентного цикла.
- Подтверждение конкретной версии, принятые замечания в DOCX, JSON, локальный тестовый ящик.
- Синий адаптивный интерфейс и отдельно опубликованная браузерная демонстрация.

## Известные ограничения

1. **OAuth не проверен с реальным аккаунтом.** Наличие исходников и тестов с имитацией сервера не доказывает доступность inference. Не заявлять обратного.
2. **Demo не выполняет смысловой анализ.** Переформулировки и отсутствующие условия могут быть пропущены. Разные события начала срока полноценно не сравниваются. Неустойки и произвольные формулы не покрыты.
3. **Числа и спецификация:** основная версия использует Decimal, но сверяет явно указанные итоги, не рассчитывает все строки, НДС и сложные таблицы.
4. **Оценка:** 44 синтетических TXT, из них 10 настройки и 34 контроля. Эталоны требуют экспертной проверки. Это не набор из 30 DOCX. Метрики реальной LLM отсутствуют.
5. **Веб-версия:** без LLM, PDF/OCR, нейросетевого поиска и облачной базы. DOCX разбирается по абзацам, включая абзацы внутри таблиц. Нестандартные документы требуют ручной проверки. Нужен современный браузер с IndexedDB, Web Crypto и DecompressionStream.
6. **Хранение веб-версии:** только браузер. Это не серверная защита неизменности. Блокировка параллельных изменений реализована в пределах вкладки; строгие транзакции между вкладками и многопользовательская работа не проверены.
7. **Почта:** тестовый ящик, реальных писем нет. Docker и скачивание весов эмбеддингов не проверены.

## Предлагаемые первые шаги

1. Запустить обе версии по README и повторить путь: пример → проверка → правка → принять/отклонить → сохранить → подтвердить → скачать DOCX.
2. Запустить pytest и evaluate.py. Прочитать три неудачных примера в отчёте.
3. Согласовать актуальное ТЗ: исходный проект использует FastAPI/ChatGPT OAuth. Позднее обсуждался другой вариант со Streamlit/GigaChat; он не реализован.
4. Если нужен новый сценарий ТЗ: сделать единственную проверку оплаты «20 рабочих дней после приёмки» против «не более 10» и ожидаемое одно нарушение. Сейчас стартовый пример иной.
5. После этого расширять покрытие смысловых условий и документов, не подменяя непроверенные случаи успешной проверкой.

## Публикация и данные

GitHub и ChatGPT Sites — разные публикации. Изменение кода в GitHub само по себе не обновляет Site: CI/CD не настроен. Для публикации браузерной версии нужен отдельный Site в аккаунте разработчика или предоставленный владельцем доступ. Служебная `.openai/hosting.json` намеренно исключена.

Локальные базы, авторизации и документы владельца не передаются. У коллеги после запуска создаётся собственная пустая база. Демонстрационные данные загружаются кнопкой. При реальной работе использовать только согласованные к передаче внешней модели документы.

Секреты держать вне Git и логов. Существующая локальная версия ограничивает Host и Origin локальными адресами: не отключать эту проверку ради публикации общего сервера без отдельной модели доступа и изоляции данных.
