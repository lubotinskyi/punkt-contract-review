# Пункт — проверка договора поставки

Локальное учебное приложение для юриста закупок. Сравнивает договор с типовой формой и внутренним положением, проверяет числовые условия и ИНН, формирует замечания с точными ссылками. Юрист редактирует и утверждает конкретную версию протокола.

## Быстрый запуск Windows

1. Нужен Python 3.12. Запустите `start.bat` из папки проекта. При первом запуске скрипт создаёт `.venv` и устанавливает зависимости.
2. Откройте **http://127.0.0.1:8000**. Не используйте сторонний домен или публичный адрес.
3. Нажмите **«Загрузить учебный пример»**, затем **«Начать проверку»**. Этот режим работает без ChatGPT и явно обозначен как демонстрационный.
4. Примите или отклоните замечания, сохраните правки, подтвердите протокол. После этого доступны DOCX, JSON и локальный тестовый ящик.

При наличии готового окружения: `.venv\Scripts\python.exe run.py`. Остановка — Ctrl+C в окне запуска. Чтобы перенести проект, копируйте исходники и ставьте зависимости заново: виртуальное окружение непереносимо.

## Проверка с GigaChat
Сервер использует GIGACHAT_CREDENTIALS (Authorization key) или зашифрованный файл Windows data/private/gigachat.dpapi. Для персонального проекта используется GIGACHAT_API_PERS. Иной scope можно указать в GIGACHAT_SCOPE. Секрет не включается в Git или JavaScript. Сертификат НУЦ для HTTPS включён в app/gigachat-root.pem.

В форме нажмите «Обновить каталог моделей», выберите GigaChat и модель. При загрузке учебного примера интерфейс выбирает demo, поэтому для живой проверки переключите режим обратно. Запуск передаёт модели текст договора и выбранные основания. Сохранённые старые проверки ChatGPT можно читать. Новые запускаются с GigaChat.

## Документы и RAG

Загрузите договор, шаблон, положение и по возможности спецификацию и справочник. Каждая загрузка получает собственный id, SHA-256 и неизменяемое содержимое. Проверка хранит выбранные версии.

Поддерживаются DOCX (включая таблицы), PDF с текстовым слоем, TXT/MD в UTF-8, CSV/JSON. До 8 МБ, 40 страниц PDF, 120 000 символов и 400 фрагментов. Страница без текста, пустой документ и неизвестный формат отклоняются. Сканы требуют внешнего OCR. PDF делится по строкам: точность границ пунктов для сложной вёрстки ограничена.

По умолчанию работает полностью локальный символьный TF-IDF поиск. Это воспроизводимый лексический baseline, **не нейросетевой семантический поиск**. Исходники также поддерживают гибридный поиск с локальными многоязычными эмбеддингами. Для него запустите `setup-semantic.bat`: установка тяжелее и первый запрос скачивает `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`. Затем вычисления локальные. Вариант с эмбеддингами реализован, но загрузка весов и качество этой модели на данном компьютере пока не проверены. Без пакета или при ошибке загрузки ошибка сообщается агенту, скрытого перехода на другой поисковый движок нет.

Имя модели задаётся `CONTRACT_SEMANTIC_MODEL`. Векторный индекс кэшируется в памяти и пересоздаётся по сохранённым документам после перезапуска. Внешний embedding API не используется.

## Агент и контроль

Модель выбирает инструменты и их порядок в нескольких раундах. Жёсткая последовательность используется только в отдельно помеченной демонстрации.

Доступны `read_clause`, `search_template`, `search_policy`, `check_numbers`, `lookup_supplier`, `validate_findings`, `finish_review`. Произвольный код, SQL, отправка почты и сетевой поиск модели не разрешены. Контекст инструмента ограничен документами текущей задачи. Содержимое файлов не может изменить права агента.

Каждый результат проходит Pydantic и проверку цитат по исходному пункту. Нарушение или согласование без основания отклоняется. Неверная ссылка, неизвестный пункт или вымышленная цитата отправляются модели на исправление. Проверка точной цитаты подтверждает её наличие, **не юридическую правильность интерпретации**. Пункты, не заявленные как проверенные, показываются в ограничениях. Заявление модели о полноте требует отдельной оценки.

Инструмент чисел распознаёт явно подписанные сроки, предоплату, гарантию и итоговую сумму. Поддерживает максимум/минимум и исключение «по согласованию». Сумма сверяется с явно указанным итогом спецификации. Это не универсальный бухгалтерский парсер: все строки спецификации, НДС, произвольные формулы, неустойки и точки отсчёта дат требуют проверки LLM/юристом. Разные единицы времени и неоднозначные поля не выдаются за успешную проверку. ИНН проверяется по контрольной сумме и наличию записи в локальном справочнике; это не проверка благонадёжности по реестрам.

Лимиты: 2–40 раундов модели, до 12 вызовов инструментов за раунд, 600 секунд между раундами, заданный бюджет токенов. В OAuth-режиме `max_output_tokens` не поддерживается, поэтому локальный бюджет прекращает **следующий** запрос и может быть превышен одним текущим ответом. Жёсткий предел расходов задаётся также в настройках ChatGPT. HTTP timeout одного ответа — 180 секунд.

SQLite хранит задачи, контекст каждого завершённого раунда, шаги, результаты и решения. После перезапуска выполнявшаяся задача становится прерванной. Её можно продолжить в пределах оставшегося бюджета. Токены и адреса авторизации не входят в журнал.

## Юрист и протокол

Экран содержит текст договора, переход к пункту, объяснение, цитаты оснований, категорию, редактор формулировки и решение. Юрист может добавить собственное замечание и выбрать источник вручную. Любая сохранённая правка увеличивает revision и сбрасывает одобрение.

Подтверждение включает revision и SHA-256 результата, комментария и исходной конфигурации. Экспорт и тестовая отправка проверяют актуальность на сервере. Устаревшая версия и отсутствие решения по замечанию блокируют подтверждение. Повторная отправка одной версии идемпотентна.

**Тестовая отправка** — запись в таблице outbox SQLite. Письмо реальному поставщику не отправляется. Итоговый DOCX содержит принятые замечания, основания, предложения и ограничения. Все замечания и решения доступны в JSON.

## Тесты и оценка

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe evaluate.py
```

`examples/evaluation/labels.json` содержит 44 синтетических договора: 10 примеров настройки и 34 итоговых. Отчёт — `reports/demo-report.md`, подробные результаты и журналы — `reports/demo-results.json`. В отчёте разобраны три неудачных прогона.

Demo precision/recall/F1 оценивают только формализованные проверки. Они не являются метриками качества LLM и не доказывают юридическую корректность. Эталоны построены на одном учебном шаблоне и нуждаются в экспертной проверке. Метрики качества GigaChat на контрольной выборке пока отсутствуют.

После входа можно явно запустить платный по лимитам подписки прогон:

```powershell
.venv\Scripts\python.exe evaluate.py --mode gigachat --model ИМЯ_ИЗ_КАТАЛОГА
```

Сопоставление замечаний идёт по стабильным id вида delivery/payment/advance/warranty/total/acceptance. Для расширения видов отклонений нужна новая разметка. Подтверждённые ложные замечания и смысловую корректность оснований нужно оценить вручную. Скрипт запускает до 34 реальных проверок — сначала проверьте лимиты аккаунта.

## Docker

```powershell
docker compose up --build
```

Откройте тот же `http://127.0.0.1:8000`. Данные сохраняются в named volume. Внутри контейнера OAuth-учётные данные создаются заново. Не меняйте порт снаружи без изменения PORT внутри: OAuth callback должен совпадать. Docker-образ здесь подготовлен, но сборка в Docker пока не проверена.

## Структура

```text
app/main.py       HTTP, загрузка, интерфейс, правки, экспорт
app/oauth.py      OAuth, проверка ID token, обновление и Responses SSE
app/agent.py      Инструменты и агентный цикл
app/documents.py  Разбор, локальный RAG, числа и проверка цитат
app/storage.py    SQLite, версии, одобрение и тестовый outbox
app/models.py     Проверяемые схемы
web/             Интерфейс без внешнего CDN
examples/        Учебные документы и 44 примера
tests/           Автотесты
reports/         Отчёт по demo и журнал трёх неудач
data/            Локальные данные и закрытые учётные записи (не публиковать)
```

`requirements-lock.txt` фиксирует проверенное окружение Python 3.12 на Windows. Базовый `requirements.txt` подходит для обычной установки. Папки `.venv`, `data` и секреты исключены из Git и архива исходников.

Опциональная проверка интерфейса: `npm install`, `npx playwright install chromium`, затем `npm run test:browser`. Перед ней запустите приложение с пустым каталогом данных на порту 8000 и без входа в ChatGPT. Тест загружает синтетические документы, создаёт демонстрационную проверку, принимает замечания и выполняет только локальную тестовую отправку. Для установленного Chrome можно задать `CHROME_PATH`. Браузерные тесты не являются зависимостью самого приложения.

## Основания проектных решений

Реализована тема 9 из презентации ТехноХаба и договорённости чата: команда из двух человек, локальное использование, собственные учебные документы, LLM не фиксируется заранее, OAuth вместо API-ключа, подтверждение юристом и измеримое качество. Готовые сторонние проекты не копировались. Документация OAuth проверена 15 ноября 2026 года:

- https://developers.openai.com/siwc/token-sharing-open-source/sign-in
- https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference
- https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions
- https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations
- https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2

Возможности OAuth находятся в preview и могут меняться. Приложение не обходит ограничения аккаунта. Перед использованием закрытых реальных договоров согласуйте передачу фрагментов внешней модели.
