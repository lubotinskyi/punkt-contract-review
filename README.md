# Пункт — проверка договоров поставки

Учебный проект: проверка проекта договора по типовой форме, положению о закупках, спецификации и справочнику поставщиков. Юрист видит цитаты, редактирует замечания, принимает или отклоняет их и подтверждает версию протокола перед экспортом.

**Репозиторий подготовлен для передачи разработки коллеге. Начните с [HANDOFF.md](HANDOFF.md).**

## Что нового с последнего обновления · 24 ноября 2026

- **Экран результатов.** В сводке появились модель, статус ИНН, шаги, токены, ревизия и счётчики по категориям. Пункты договора подсвечиваются и связаны с карточками замечаний. Матрица правил и журнал вызовов агента открываются отдельными вкладками.
- **Работа с протоколом.** Карточки показывают цитату договора, норму, объяснение и предлагаемую формулировку. Решения юриста, сохранение, подтверждение, экспорт и тестовая отправка доступны из отчёта. После изменения версии требуется новое подтверждение.
- **Агент GigaChat.** Проверка проходит через несколько вызовов инструментов. Сервер восстанавливает точные цитаты по идентификаторам, проверяет привязку к правилу и сохраняет корректные замечания после повторных ошибок валидации. Открытые вопросы остаются видны в завершённом отчёте. Системные инструкции требуют игнорировать команды в тексте договора.
- **Документы.** Улучшены чтение объединённых ячеек DOCX, склейка переносов в нумерованных пунктах PDF и распознавание исключений по срокам поставки с уточнением в скобках.
- **Оценка.** Сохранены [отчёт по 34 договорам](local-app/reports/gigachat-report.md) и [отчёт по трём сложным кейсам](local-app/reports/gigachat-three/gigachat-report.md). На живом прогоне GigaChat-3-Ultra по 34 синтетическим договорам F1 составил 0,5349, 26 проверок завершились и 8 прервались. Прогон зафиксирован до последних правок по стресс-тесту и интерфейсу.

## Две версии приложения

| Папка | Назначение | Хранение | Подключение модели |
|---|---|---|---|
| `local-app/` | Основное Python-приложение: FastAPI, SQLite, python-docx, локальный поиск | Локальная SQLite | GigaChat API или локальная проверка по правилам |
| `web-demo/` | Опубликованная браузерная версия для ChatGPT Sites, HTML/CSS/JavaScript | IndexedDB браузера | Проверка по правилам |

Сайт: https://punkt-contract-review.anikaazimova.chatgpt.site

На сайте работают формализованные проверки и весь путь юриста до DOCX/JSON. Это самостоятельная демонстрационная реализация, а не размещённый Python-сервер. История между устройствами не синхронизируется. Очистка данных браузера удаляет её.

## Запуск основной версии на Windows

Нужен Python 3.12.

```powershell
git clone https://github.com/lubotinskyi/punkt-contract-review.git
cd punkt-contract-review\local-app
.\start.bat
```

Откройте http://127.0.0.1:8000. Добавьте договор, типовую форму и положение. Выберите «Проверка по правилам» и нажмите «Начать проверку». Этот режим работает без ключа. При первом запуске зависимости скачиваются из интернета.

Если окружение уже установлено:

```powershell
.\.venv\Scripts\python.exe run.py
```

Данные создаются в `local-app/data/`. Не коммитьте эту папку. Дополнительные настройки и ограничения — в [local-app/README.md](local-app/README.md).

## Состояние опубликованной версии

18 ноября обновлены выбор комплекта, фильтрация замечаний, мобильная вёрстка и обработка сбоя модели. Основной локальный GigaChat работает через сервер с сертификатом НУЦ. В публичном ChatGPT Site доступна проверка правилами. Серверный запрос для GigaChat на этом хостинге получил 502 при получении токена, поэтому онлайн-режим отключён в интерфейсе.

Серверный код публикации находится в hosting/worker.mjs. Для сборки выполните python hosting/build.py. Нужны секрет GIGACHAT_CREDENTIALS, привязка R2 BUCKET и доступ к обоим HTTPS-сервисам Сбера. Проверить доступность до установки GIGACHAT_ONLINE=1. Атомарные записи R2 ограничивают все вызовы модели 30 попытками суммарно, без ежедневного сброса. Максимум 14 000 символов JSON с документами и 1 400 выходных токенов. Это лимит использования, не гарантия фиксированной цены. Не очищать записи квоты при обновлении приложения. Ключ в репозиторий не включён.

## Запуск веб-демонстрации

Из корня репозитория:

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory web-demo
```

Откройте http://127.0.0.1:8765. Запуск через двойной щелчок по HTML не поддерживается: нужны HTTP и возможности безопасного контекста браузера.

## Проверки

Из `local-app/`, после установки зависимостей:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe evaluate.py
```

Прошли 44 Python-теста и отдельный сценарий Playwright в Chrome. Браузерный тест проверяет навигацию между пунктом и замечанием, вкладки, сохранение, подтверждение, DOCX, тестовую отправку и вёрстку на 1440 и 390 px. Для запуска используйте `node tests/browser.cjs` при работающем локальном сервере и установленном Playwright.

На 34 контрольных примерах в режиме правил precision составил 1,0, recall — 0,9444, F1 — 0,9714. [Отчёт проверки по правилам](local-app/reports/demo-report.md).
